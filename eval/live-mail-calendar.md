# 第一轮真实账号测试：邮箱与日历

状态：**待执行**。这是专用账号中的合成业务验收，不是原书全部用例的成功证明。

## 1. 连接专用账号

先安装技能集，再在 Cola 中说：

```text
我要用专用测试账号验证邮箱与日历。
测试邮箱是：[填写地址]。请指导我连接这个邮箱和测试用的 Google 日历。
密码、验证码、授权码不要让我发到聊天里。
连接后，只核对账号身份，并告诉我可用的日历名称和时区。
先不要发邮件、删除邮件或创建日程。
```

Google 日历授权不等于 Gmail 授权，两者需要分别连接。如果没有专用账号，先准备一个；不要把日常邮箱作为替代。遇到服务未就绪、网络或授权失败，记录具体阻塞步骤，不能记为测试通过。

## 3. 在 Cola 中测试邮件检索和计算

```text
请使用 Muse 技能，只读测试邮箱 [填写地址] 的收件箱，搜索主题含 COLA-MUSE-TEST- 的邮件。
完整读取这批测试邮件，列出主题、邮件 ID、订阅 ID、状态、金额与周期。
算出仍有效的固定订阅每月和每年共花多少钱；取消和不明确的项目单独列出。
不要发送、移动、删除邮件，也不要主动修改已读标记。说明所用读取方式是否可能自动标记已读。
交付一份审计文件，并保留每个结论对应的邮件证据。
```

独立验收：四封邮件均找到，历史邮件分别记录月付 CNY 20 和年付 CNY 120。**仅凭这些邮件，不得声称已核实当前仍在续费，也不得将 CNY 30/月、360/年说成确认中的持续支出。** 它们是历史资料的折算，不是当前账户状态。关闭续费的明确测试通知可作为该演示记录的取消证据，过期时仍需复核；未知项保持待核实。重跑不得因为收发副本或重复检索而累加。若需要测试确认总额，另外提供明确标为合成数据的当前账户观测，绝不能伪造真实服务状态。用官方邮箱网页复核内容；如果读取导致已读状态变化，如实记录，不称为完全无状态变化。

## 4. 测试日历创建、改期与重跑

填写上一步确认的日历。选一个未来日期，保持两次请求使用同一日期和事件编号：

```text
请使用 Muse 技能，在专用测试账号 [填写地址] 的日历 [填写名称或 ID] 中创建一个演示事件。
事件编号：COLA-MUSE-DEMO-01；标题：Cola Muse 日历测试。
日期：[填写未来日期]；时区：Asia/Shanghai；开始 15:00，结束 15:30。
这次测试允许创建、改期、重复执行和最终删除这一条演示事件。
不要邀请任何人，不发通知，不创建会议链接或提醒；不要修改其他事件。
请先检查该编号是否已存在；记录返回的事件 ID，再读回核对账号、日历和时间。
```

创建后到 Google 日历网页核对，再发：

```text
把刚才 COLA-MUSE-DEMO-01 演示事件改到同一天 16:00–16:30，仍用 Asia/Shanghai。
保留原事件 ID；读回确认旧时间已替换。不要新增第二条。
```

重复发送一次改期请求。验收：指定日历中仍只有一条该编号的事件，ID 不变，时间为 16:00–16:30；其他事件不变。

最后发：

```text
删除本次测试创建、编号为 COLA-MUSE-DEMO-01 的演示事件。
按之前记录的事件 ID 核对后操作，只处理这一条。
删除后复查，告诉我它是已取消、已删除，还是结果未知。
```

验收：事件不再作为有效日程出现；服务返回的取消/删除状态与网页一致。超时不是成功，不要盲目重建或删除。清理也需保存结果。

## 5. 保存结果

每项记录 `pass / fail / blocked / not_run`、日期、Cola 版本、使用技能、预期、实际、重跑结果和清理结果。只有独立读回或网页核对后才能标为 `pass`。如果由人直接调用接口完成，应记为连接器测试，不能记为 Cola 技能端到端通过。

原始邮件、账号地址、日历 ID、事件 ID、授权日志只存本地；公开报告用脱敏证据和结果，不上传凭证或私人截图。首次测试尚未完成前，[验证报告](../docs/verification.md) 的真实账号成功数保持 0。
