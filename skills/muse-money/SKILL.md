# 订阅与支出审计

先读取 [执行与验收约定](references/contract.md)。开始规范化资料前，读取 [v2 数据与证据约定](references/data-contract.md)。

## 先确定证据与范围

- 用已知账号、时间窗和目标继续工作；默认值先简短说明。邮箱只读任务先读当前邮箱连接技能的完整入口，再按其版本与服务商指引执行，不能靠旧 CLI 记忆猜命令。若用户只说“测试”，先用合成资料或已指定测试账号。
- 记录检索时间窗、文件夹、各查询分页、错误和局限。满页继续查；中文查询报错时先核对当前连接器语法，再用已支持的分页列表在本地筛选或可靠的发件人检索补查。替代查询可能漏掉未知商户，应明确标记部分覆盖，不能把接口失败说成“没有邮件”。
- 邮件 ID 必须带账号别名和文件夹，跨来源优先按交易 ID / Message-ID 去重。下载账单附件后核对正文，不能只凭标题认金额。不要读取无关邮件或把原始财务资料发布到公共仓库。

## 审计与交付

1. 分开记录历史付款、当前自动续费、当前费率、下一期报价和已付权益。旧收据、促活、续费提醒、未收到新邮件都不能独立证明当前续费设置；证据冲突就待核实。
2. 按 v2 保留未知金额/币种为 null、未知周期为 unknown。税前金额缺税额时不混入含税总额。不用占位数据计算所谓年费上限；充值也不代表余额已经消耗。
3. 运行 `scripts/audit-subscriptions.mjs input.json audit-result.json report.md`，一次生成账本与报告。汇总先按币种分开，清楚区分当前费率年化、下一笔扣款和历史支出。证据不足导致无确认总额时，先展示已找到的历史付款与待核实项目，不能说没有支出。
4. 回复先给简短结果：已核实续费的项目与金额、即将扣款、待核实事项、覆盖局限，再附报告。每个数字与日期引用脚本结果；不重新口算，不使用未经检查的“未来 30 天”。使用频率不能从收据或营销邮件推断。
5. 较长检索先交付已核实的部分与当前缺口，随后补全。用户无需理解代理、CLI、路径或权限代码；普通回复只解释结果和下一步，调试详情留在本地记录。

## 取消与更新账本

用户已经指定取消对象和范围时继续执行，无需重复询问同一授权。先识别收费渠道，查看该服务的实际入口与当前规则，再判断能否代办；不能仅凭发件人就保证全流程成功或断言无法操作。

按用户浏览器偏好操作；登录接管要交还已有空间并提供可找到的入口，用户确认后恢复。退出任务按浏览器技能的完成流程收尾。只取消不等于退款，不发起用户未要求的退款，也不编造离开原因或使用情况；若表单必须选择而没有中性选项，再询问缺失原因。

取消后重载读回账号、订阅、自动续费关闭与权益结束时间。确认后运行 `scripts/record-cancellation.mjs`，同时生成新的账本、汇总和报告，保留取消前快照。不要只给旧报告追加一句而留下错误的当前账本。服务返回不明确时记录结果未知，先查状态再决定是否重试。
