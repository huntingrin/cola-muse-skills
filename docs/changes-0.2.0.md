# v0.2.0：订阅审计证据与账本修正

本次根据用户真实使用反馈修正技能，回归材料为重新编写的合成数据，不包含用户邮件、账户、订阅清单或浏览器截图。

## 解决的问题

| 问题 | 现在的行为 | 验证方式 |
| --- | --- | --- |
| 用旧收据推断当前扣款 | 自动续费观测与历史付款分开；仅付款/续费提醒不能进入确认总额 | 收据、提醒、过期与冲突状态回归 |
| 周期未知却填 monthly | unknown/null 为合法数据，不参与年化；v1 输入明确拒绝 | 未知周期/金额/币种回归 |
| 税前税后、旧价新价混算 | 当前含税费率、历史付款、下一期报价分开 | 税额、涨价和报告一致性回归 |
| 时间窗与日期不一致 | 统一开始日包含、结束日排除，30 天边界由脚本计算 | 边界日、未来证据、过去扣款日回归 |
| 满 500 封误认为检索完整 | 完整性来自逐页记录；满页、错误和时间窗冲突均降级 partial | 分页/错误/窗口回归 |
| 取消后旧账本仍计费 | 保留原快照，在新目录一起生成关闭续费后的 JSON、计算结果和报告 | 取消、权益保留、重复执行、旧文件保护回归 |
| 经目录别名启动脚本静默退出 | 安装器及技能脚本按真实路径判断入口 | 通过目录符号链接启动全部 CLI 的回归 |
| 连接时猜命令或误判权限 | 先读实际连接器入口；检查与修复分开；不读凭证文件诊断、不责怪用户 | 技能指令审阅；仍需真实 Cola 行为复测 |
| 普通回复被实现细节淹没 | 先给结果、待核实、覆盖范围和下一步；调试细节留本地 | 技能指令审阅；仍需真实 Cola 行为复测 |

## 使用变化

- 技能总数仍为 25，安装与更新方式不变。
- `muse-money`、`muse-connect`、`muse-inbox` 更新到 0.2.0；`muse-family`、`muse-learn` 仅修复脚本入口的路径别名识别，业务计算不变。其他技能内容保持原版。
- 审计数据升级为 schema v2。迁移见 [数据约定](../skills/muse-money/references/data-contract.md)，不把旧 active 自动变成已核实续费。
- `record-cancellation.mjs` 只记录**已经核验的取消结果**，它不会连接商家或执行远程取消。
- 报告从与 JSON 相同的结果生成，减少二次口算与叙述偏差。

## 验证边界

新增测试证明脚本在合成输入上的处理规则，不证明模型总能从任意邮件提取正确事实。证据引用也不是自动鉴真机制。尤其是账户连接、网页接管、查询召回率、人工原因选择和模型回复质量，仍需要使用新版技能进行现场复测。

历史 v0.1.0 的 3 个 Cola 合成任务结果保留原版本标记，不能算作 v0.2.0 订阅审计已通过模型实测。真实反馈中记录的商家取消成功与审计缺陷分开处理，不发布私人原始记录，也不把整个审计标为 live_pass。
